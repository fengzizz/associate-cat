# Plan Code Handoff

读取同目录 `plan-implementation.md` 处理 Plan 专属条件。本文件仅补充目标、任务和实际产物的对应与核对，不增加授权、实施等级或固定报告流程。

## 理解计划依据

复用所选范围的当前设计、约束、任务责任、实际依赖和验收。按全文语义理解，不依赖某个语言的固定标题；已有 change point 保持原 Task 归属。后置评估只用于提示复核，不直接成为新增实施范围。

尽量遵照计划要求。缺少普通实现细节不等于计划不可施工；实际冲突的局部微调、严重错误停止遵守主 Skill。只有缺可发现的施工信息时才按主 Skill 读取 `implementation-baseline.md`，不重建完整消费清单。

## 目标与结果核对

结合实际修改检查所选目标是否落实、关键约束是否满足，以及是否混入无关内容。默认简短说明完成项、必要局部调整、重要偏差和验证结果；复杂关系或具体风险需要时再补详细对应。不要求逐元素台账、固定正反两份报告或每 Task 一条验证命令。

- 源码、非源码或验证任务分别对应其实际产物与验收，非源码不套源码字段。
- 保留任务责任和验收含义；普通核对可融入阅读、实施和最终 diff，不强制单独分阶段。
- 不把计划内允许的必要局部微调自动判成严重偏离，也不把新设计或目标变化包装成普通实现细节。
- 有验证矩阵时覆盖选中范围的验收项；可共享检查或合并结果说明，不删除明确要求，不虚构验证编号。

## 最低验收标准

所选任务有明确结果：已落实、经核实无需改动，或尚未完成并说明原因。结果可以是源码、非源码产物或验证执行。必要验收的证据和未覆盖项应清楚，不以无关修改凑产物，不因缺记录形式制造阻塞。

按主 Skill 如实区分完成、已验证、失败、未验证和阻塞。只在必要实施与验证均满足时说明对应范围闭环；范围内偏差按主 Skill 修正，其他问题说明影响与所缺输入，不在交付时改写 Plan。

## 输出语言

默认在对话中使用 Interaction Language；明确获准写入某文档的内容使用该文档的 Output Artifact Language。语言引用仅由主 Skill 按条件加载。详细映射并非常驻输出，不因存在受控字段而实例化完整报告。
