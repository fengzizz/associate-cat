# 计划实施规范

本规范定义 `cat-code` 解析实施输入、确认当前实施目标、建立边界并连续落地代码时的通用门禁。项目规则在本规范上追加语言、系统和验证要求。

## 输入与路由

- 每次使用 `cat-code` 编写代码时读取本规范。
- 语言只影响用户可见显示文本，不影响输入路由、当前实施请求、实施前门禁、本轮允许修改的范围、停止条件或验证结论。需要语言 reference 时只由 SKILL.md 按条件直接加载。
- 实施输入可以是当前对话中已经形成的 Plan、用户明确指定的持久 Plan，也可以是边界明确的直接实施请求。输入 Plan 默认是只读 source；被选作实施范围不等于其文件已经是可写的 `Current Plan Document`。
- 不因进入实施阶段而自动创建 plan、进度文件或其他持久文档。
- 输入为 plan、任务拆分、评审结论或等价计划文档时，再读取 `plan-code-handoff.md`。

输入分为三类：

1. **Ready plan**：目标、边界、任务、依赖、行为后果和验证信息足以施工；建立 plan—代码映射后实施。
2. **边界明确的直接请求**：用户明确要求编码、修改或修复，且目标和范围足以建立最小施工基线；不强制创建正式 plan。
3. **粗略文档或设计不足的请求**：可以只读调查并列出缺口；如果缺口会改变行为、所有权、状态、生命周期、接口、控制流、失败处理或验证结论，则停止当前实施批次并报告问题，不在 Code 阶段补成新设计。

## 当前实施请求与目标范围

用户当前明确要求编码、修改、修复或实施指定 plan/Task，决定本轮是否进入代码写入以及处理哪些目标；plan/Task 的可执行状态和施工门禁决定目标能否实际写入，本轮允许修改的范围决定可以写到哪些对象。

- 对已有 plan，用户当前实施请求确定本轮 plan 或 Task 范围；不从 plan 中读取或要求持久实施授权。
- 对没有 plan 的边界明确任务，用户当前明确的编码、修改或修复请求确定本轮直接目标范围。
- 仅调用 Skill 名称、plan 为 Ready、用户要求继续分析、只提供参考文档或一般性“看看”，都不表示用户要求实施。
- 本轮实施范围不因任务复杂、编译失败、测试失败、实现方便或任务紧急而扩大。
- 当前实施请求本身不写回 Plan。只有 Direct User Request Prose 另行要求保存、刷新或同步进度，且写回目标已经无歧义地建立为 `Current Plan Document` 时，才按“进度与评审”规则维护该 Plan 文档。

## 实施前门禁

开始首个写入前核对：

- 已读取当前项目适用的规则、代码规范、允许修改边界和验证入口。
- 当前事实仍与请求或 plan 依据一致。
- 用户当前实施目标明确，本轮 Task 或直接请求范围与该目标一致。
- 当前 Task 为 Ready，且不存在未就绪的上游依赖；直接请求已经形成最小施工基线。
- 当前实施范围不受 Open 决策、阻塞性事实缺口或 Not Ready 上游影响。
- 文件或定位方法、关键对象、行为后果、失败与清理、验证和停止条件足够明确。
- 已建立本轮允许修改的范围；独立 Validation Task 的范围为空。

任一项不成立时，立即停止当前实施批次并报告缺口；报告继续实施所缺少的最小目标、事实、权限或范围，不在 Code 阶段补充设计、修改 plan 或继续写入。不要用“局部细节”“编译修复”或测试通过掩盖设计缺口。

## 本轮允许修改的范围与局部实现细节

- 对 plan 输入，按显式文件列表、In Scope / Out of Scope、点名对象、实现步骤和最小必要直接依赖建立本轮允许修改的范围。
- 对直接请求，从用户点名对象和完成目标所必需的最小代码面建立集合，并在首次写入前紧凑披露。
- 局部实现细节必须能从当前已确认约束唯一推导，且不改变目标、职责边界、公共行为契约或风险接受。
- 保护分支、判空、默认值、初始化、接线或绑定顺序、状态、控制流、失败处理和局部 helper 都可能改变语义；只有属于本轮实施 Task 并被当前设计唯一约束时才能编写。
- 新增公共基类或工具、批量修改调用方、增加计划外模块、公共接口、配置结构或仅为整洁、调试和未来复用增加包装，不属于可自行补齐的局部细节。
- 发现必须修改本轮允许修改的范围之外的内容时，立即停止当前实施批次，报告范围外对象、新增影响面、必要原因和不修改的后果；不得修改范围外对象，也不得在 Code 阶段建议或建立新的 Task。

## 紧凑批次披露

首次写入前给出紧凑施工基线，不预先铺开所有未来代码：

- `Current Plan` 或直接请求语境。
- 用户当前实施目标和本轮任务范围。
- 任务 ID 或直接请求目标。
- 预计文件、关键对象和行为后果。
- 主要风险、局部验证和停止条件。
- AI 将在该边界内连续编写语义代码。

该披露用于让边界可见，不是逐 Task 审批流程；没有阻塞时不等待重复确认。

## 连续实施节奏

- 按真实产物和接口依赖构建执行顺序；Task ID 是稳定身份，不是固定执行位置。
- 显示顺序存在前向依赖时可以调整本轮队列并报告；依赖无法消解、中间状态不安全或需要新增设计决策时，立即停止当前实施批次并报告阻塞，不继续调度其他 Task。
- 在当前实施批次内连续处理 Task，不在 Task 之间等待用户回复；内部仍按边界逐项实施，不把连续执行解释成整块重写。
- 进入每个 Task 的首个代码步骤前，内部重新核对 Task Readiness、关联当前设计与有效的 Decided 记录或带来源约束、实现/验证卡片、上游依赖、前序局部验证和安全中间状态、本轮允许修改的范围、行为不变量、局部验证和停止条件，并确认批次预检后没有出现新的事实或 plan 冲突。没有阻塞时不重复询问是否继续本轮实施范围。
- 严格消费 plan 的 Task 责任边界，不在代码阶段静默合并、拆分或改变 Task 语义。
- 每个 Task 结束时检查实际落点、本轮实施边界、局部验证和明显偏离；不固定执行全量反向核对。
- 批次结束后统一执行双向核对；发现结构、行为、调用顺序、失败路径或验证语义已经偏离时立即停止，不等待最终核对。

## Validation Task

- plan 明确包含独立 Validation Task 时，将它作为本轮允许修改的范围为空的验证单元排入依赖队列。
- 起始门禁只核对 Ready、依赖、验证目标、步骤、允许执行边界和停止条件，不生成代码步骤。
- 只执行当前请求、项目规则和宿主权限允许的验证；破坏性操作、外部发布或宿主要求单独批准的动作不因当前代码实施请求自动获得许可。
- 验证暴露能够由当前设计唯一推导修正方式的实现偏差时，返回对应实施 Task；暴露设计问题时，立即停止当前实施批次并报告问题，不在 Validation Task 中补写代码或设计。

## 程序编译验证或语法校验

对于程序编译验证或语法校验这种纯粹的验证流程，发现简单的语法问题或是声明错误等，只做不会破坏程序完整性和逻辑闭环的保守修改。
期间如果发现简单的修改矫正依然无法通过，应该及时停止，并说明错误原因。

## 停止与问题报告

以下任一情况成立时，立即停止当前实施批次：

- 当前事实与 plan 或请求的相关依据冲突。
- 需要改变目标、Task 语义、架构、公共行为契约或风险接受。
- 必须修改本轮允许修改的范围之外的对象。
- 存在多种合理设计，无法由当前约束唯一收敛。
- 实施中出现多个会改变行为、职责边界、兼容、主要风险或验收的合理方案；Code 阶段不自行建立或解决新的设计决策记录。
- 验证失败暴露新设计问题，而不是本轮实施范围内的实现偏差。

停止后只报告当前 Task 或请求、停止阶段、已完成且仍有效的修改、尚未实施的内容、阻塞事实与证据、现有 plan 或请求为什么不足、受影响范围、验证状态，以及继续实施所缺少的事实、权限或明确边界。已经完成且仍符合当前设计和本轮允许修改的范围的局部结果可以保留。不得修改 plan、建立新的设计决策记录、比较新方案、提出新的 Task 拆分或自行启动规划；是否另行规划由用户决定。

## 进度与评审

- 默认对话中的 Progress 使用 `Interaction Language` 对应显示集；只有实际写入某个文档时才使用该文档的 `Output Artifact Language`。zh-CN 显示源为 `未开始 / 进行中 / 阻塞 / 已完成 / 已验证`。同时报告实际文件与对象、必要验证结论和方案偏差。
- `Completed` 语义表示实现已落地并通过当前轻量检查；`Verified` 语义表示任务要求且获准执行的必要验证已经通过。显示名按所属输出表面的语言选择，两者不得合并，也不得因为实现完成就自动进入 `Verified`。
- 只有 Direct User Request Prose 明确要求保存、刷新或同步进度，并且目标是无歧义的 `Current Plan Document` 时，才把精简快照写回该 Plan 文档。目标不明确时保持 source artifact 只读，在对话中报告实际进度；不得按仓库位置、文件名、标题、主题、内容相似度或其他任务文档猜测写回目标。
- 不记录命令流水、反复修改过程、完整日志、大段 diff、聊天记录或主观百分比，也不创建独立进度文档。
- Task 被合并、拆分或改变语义后，重新核对关联设计、change point、依赖、`Task Readiness`、本轮实施范围和本轮允许修改的范围；稳定 ID 不延续旧语义的实施边界。
