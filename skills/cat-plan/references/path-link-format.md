# Path Link Format

仅在输出文件路径，尤其是决定“用户可见路径文本”和“本地跳转目标”格式时读取本文件。
特别是AI主体运行环境和用户的应用环境不在一起的时候，比如 AI 实体在虚拟机里运行，用户却是在 Windows 中使用 AI，这时的链接可能就涉及到格式转换。

## 规则优先级

- 先服从 system、developer 和宿主定义的输出契约，再应用本文件默认规则；不要用本文件覆盖更高优先级约束。
- 在不违反上层约束的前提下，按用户明确指定的路径格式输出，并把覆盖限制在指定场景。
- 默认对工程内文件显示仓库根相对路径，对工程外本地文件保留绝对路径语义。
- 始终分离**展示文本（label）**和**链接目标（target）**；不要让 target 格式反向改变 label。
- 路径、文件名、扩展名、行列后缀和 Markdown 链接 target 不本地化。只有说明性的用户可见 label 才跟随其所在输出表面的语言；以文件名、路径或目标原名作为 label 时保持原文。语言选择不得改变 Windows/WSL 映射、仓库归属判断或可点击 target。

## 决策顺序

1. 识别 URL、工作项地址和其他明确协议；命中时保持原样，不进入本地路径转换。
2. 从路径末尾分离数字型 `:line` 或 `:line:column` 后缀；保留 Windows 盘符后的冒号。
3. 使用 `git rev-parse --show-toplevel` 解析当前 Git 仓库根目录；不要默认使用 cwd、workspace 或某个嵌套目录。
4. 规范化本地路径；仅在宿主存在明确映射时转换 Windows/WSL 盘符形式，不要硬编码盘符。
5. 按完整路径段判断仓库归属；不要用会误判同名前缀目录的字符串前缀比较。
6. 生成 label 并重新附加行列后缀；仅在需要可点击性时独立生成 target。

## 输出矩阵

| 对象 | 用户可见文本（label） | 链接目标（target） |
| --- | --- | --- |
| 工程内已有文件 | 使用 `/` 分隔的仓库根相对路径 | 对话中服从宿主契约；持久化 Markdown 中按文档所在目录计算相对 target |
| 工程内规划文件 | 使用仓库根相对路径 | 文件不存在时不生成链接 |
| 工程外 `/mnt/<drive>/...` 文件 | Windows-facing 输出转换为 `<DRIVE>:/...` | 按宿主协议生成 |
| 工程外其他本地文件 | 保留规范化绝对路径 | 按宿主协议生成 |
| URL、工作项、SVN，Git 地址 | 保持原协议 | 保持原协议 |

- 未收到上层或宿主的可点击要求时，默认只输出 label。
- 持久化 Markdown 的普通相对链接从 Markdown 文件所在目录计算；无法确定文档位置时使用纯文本。
- 仅在上层或宿主明确要求时使用绝对 target 或专用跳转协议。
- 保持 `/home`、`/run` 等没有稳定 Windows 映射的 Linux 绝对路径不变。

## 回退规则

- 无法解析 Git 仓库根目录时，不猜测固定工程根；保留输入，并明确路径基准未知。
- 无法确认目标存在或文档位置时，保留纯文本，不生成失效链接。
- 无法确认 Windows/WSL 映射时，不转换盘符风格。
- 无法确认宿主跳转协议时，不生成本地链接。
- 发现同名前缀目录时，按完整路径段重新判断归属，避免把仓库外目录误判为工程内路径。

## 关键示例

- 在对话中引用工程文件时，显示 `source/file.cpp:42`；若宿主要求可点击，允许 target 使用 agent 可见绝对路径。
- 从 `plan/plan_A.md` 链接 `source/file.cpp` 时，显示 `source/file.cpp`，普通相对 target 使用 `../source/file.cpp`。
- 引用尚未创建的 `source/newfile.h` 时，只显示该仓库根相对路径。
- 在 Windows-facing 输出中引用工程外 `/mnt/c/Users/example/spec.md` 时，显示 `C:/Users/example/spec.md`。

## 质量门禁

- 检查工程内文件的可见文本是否全部使用仓库根相对路径。
- 检查持久化 Markdown 的普通相对 target 是否从文档所在目录计算。
- 检查绝对路径是否只用于工程外 label、上层要求的 target 或用户明确指定的场景。
- 检查 target 格式是否改变了 label，规划文件是否生成了虚假链接。
- 检查路径行列后缀和实际盘符是否被完整保留。
