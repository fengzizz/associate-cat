# plan Output Template

本文件定义 Associate Cat 正式计划的默认输出模板。

## 使用规则

- 下方中文内容是正式 Plan 的唯一结构源和 zh-CN 显示源。英文输出必须逐项使用 terminology 的固定 heading、label、status、concept 和 pattern，不得对模板骨架作同义改写；第三语言按 terminology 语义锚点生成。所有语言保持相同章节顺序、层级、条件和字段语义。模板本身不读取语言 reference，也不包含第二套完整模板或 `{{...}}` 占位符。
- 正式计划使用下方模板；前 4 章和末尾“方案评估与建议”是默认保留骨架，不允许替换或调整顺序，内容可按任务必要性压缩。
- 核心功能要足够详细，其他部分保持简明；中间章节可按任务需要裁剪、合并或扩展。
- “方案评估与建议”的内容标准读取 `plan-evaluation-criteria.md`。
- 先将用户特殊要求归入目标与范围、实现方案、算法细节、架构细节、任务拆分、验证或后置评估；能用子标题承载时不新增主章节。
- 只有特殊要求无法自然归入现有章节时，才在第 4 章之后、“方案评估与建议”之前增加必要主章节；不得用临时标题替换模板主干。
- 当用户的主要交付物是独立评审、评估或复核报告而非正式计划时，不强制套用本模板。
- 实例化模板前，按改动点判断是否涉及源码实现；混合计划逐项判断。只保留实际适用的章节和字段，不用占位值填充不适用维度。
- 任务类型使用与当前改动相匹配的名称。正式 plan 页首保留两个 plan 级状态：`Document Status` 和 `Design Readiness`；决策记录和 Task 的局部状态分别由对应字段负责，不计入 plan 级状态数量。
- 模板中的很多可选项通常是因为非源码内容实在不使用，才设为可选的。对于源码相关的内容，还是要按任务实际涉及的维度尽量填充。`Current Plan` 只保存当前有效的事实、当前设计、必要的设计决策记录、任务和验证，不保存普通修订过程、旧决策结果或失效方案细节。
- 模板中标题或字段后的“若有、如适用、实际涉及时保留、涉及时必填、按执行顺序、需要独立解释时使用”等括号文字属于模板作者给实例化者的条件或顺序指令，不属于受控显示值，也不得原样写入最终 Plan。实例化时先执行条件并保留或删除对应结构，再只输出 terminology 定义的基础 heading/label 或固定协议字面值。未命中的条件不输出占位项，除非模板明确规定该字段常驻。若未来确需让条件文字本身成为用户可见内容，必须建立独立受控 pattern。
