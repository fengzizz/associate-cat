# 项目上下文

开始规划前，用当前任务所在位置发现项目自身的规则和事实，不在本 Skill 中预设项目类型。

## 项目概况

如果项目本身定义了项目规则、代码规范或相关文档，先了解与当前任务直接相关的结构、规则、事实来源和验证入口，确保后续分析、方案、Task 与验证建议符合项目要求。
优先遵循适用的 `AGENTS.md` 或等价公共规则；嵌套规则只补充真实局部差异。
如果项目规则、`Current Plan` 与用户要求发生冲突，先按规则层级和用户目标识别冲突；不能在当前规划责任内闭合时，明确受影响范围和所需输入，不用“综合考虑”掩盖冲突。

## 发现顺序

1. 解析当前版本管理仓库或用户明确指定的项目根目录。
2. 读取适用的 `AGENTS.md`、项目规则、代码规范和 Skill 指令；嵌套规则只补充真实局部差异。
3. 查找与当前任务相关的项目地图、知识文档、构建入口、测试入口和模块说明；项目提供检索索引或定位工具时优先使用。
4. 按用户点名对象、行为关键词、文件、symbol 和直接依赖定位真实实现面。
5. 将稳定项目事实与本次任务推断分开；项目事实发生冲突时，以更高优先级规则和当前源码为准。

## 使用边界

- 项目规则是方案设计和验证判断的重要输入，不复制进通用 Skill。
- 不因缺少某种固定目录、语言、框架或工具而假定项目不完整。
- 只读取足以约束当前任务的项目上下文；不要把整个仓库文档无差别加载进上下文。
- 找不到关键规则或验证入口时，在 plan 中明确缺口及其影响，不编造默认规则。
